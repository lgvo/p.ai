`architecture/` is the current account of P's system structure; where it and
the code disagree, the code is the source of truth. Other live documents are
authoritative for the subject the authority map names them for.

`archive/` holds P's design, status and plan documents and the interface
rework record as of 2026-11-04. They are non-normative history: read them for
past rationale, never as authority. Never edit a file under `archive/` except
to fix a link.

Before substantial design work or a consequential documentation decision,
read `../PROJECT.md` and route the subject through its authority map.

- Keep each normative rule in one live document.
- When a subject needs a new design or reference document, create it in
  `docs/`, beside the architecture account, and add it to the authority map.
- README summarizes the product and links to design documents.
- Temporary review documents record pending decisions and are deleted after incorporation.
